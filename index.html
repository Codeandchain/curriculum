Canevas validé

Le client signé

HMAC-SHA256 avec le Client Secret, encodé en hex, selon le format documenté par Bitnob. On signe et on envoie exactement la même chaîne JSON.

bitnob.js
import crypto from 'node:crypto';
import 'dotenv/config';

const { BITNOB_CLIENT_ID: ID, BITNOB_CLIENT_SECRET: SECRET } = process.env;
const BASE = 'https://api.bitnob.com';

export async function bitnob(method, path, body) {
  const payload = body ? JSON.stringify(body) : '';   // GET = chaîne vide
  const ts = Math.floor(Date.now() / 1000).toString(); // secondes
  const nonce = crypto.randomBytes(16).toString('hex');
  const signature = crypto.createHmac('sha256', SECRET)
    .update(`${ID}:${ts}:${nonce}:${payload}`)
    .digest('hex');

  const res = await fetch(BASE + path, {
    method,
    headers: {
      'Content-Type': 'application/json',
      'X-Auth-Client': ID,
      'X-Auth-Timestamp': ts,
      'X-Auth-Nonce': nonce,
      'X-Auth-Signature': signature,
    },
    body: payload || undefined,  // la chaîne signée, telle quelle
  });
  return res.json();
}

// Checkpoint 2.3
console.log(await bitnob('GET', '/api/whoami'));

Le webhook en local

On crédite l'utilisateur à la réception du webhook, jamais sur la seule réponse du front.

server.js
import express from 'express';

const app = express();
app.use(express.json());
const vus = new Set(); // références déjà traitées

app.post('/webhooks/bitnob', (req, res) => {
  const { event, data } = req.body;
  if (vus.has(data?.reference)) return res.sendStatus(200);
  vus.add(data?.reference);
  console.log('Webhook :', event, data);
  // transfer.success → paiement Lightning réglé
  // deposit.success  → BTC on-chain reçu
  res.sendStatus(200);
});

app.listen(3000, () => console.log('Écoute sur :3000'));
// puis : ngrok http 3000

La forme exacte du corps des webhooks et leur vérification de signature sont confirmées par l'équipe avant le bootcamp.

401 intermittentHorloge décalée (fenêtre de ±5 min) ou timestamp en millisecondesSynchroniser l'heure, diviser Date.now() par 1000

Bonnes pratiques

Secret côté serveur

Le Client Secret ne va ni dans le front ni sur GitHub. .env dans .gitignore.

Une référence par opération

Stocker l'état de chaque opération et ignorer les doublons.

Attendre les confirmations

On-chain : au moins 3 confirmations avant de créditer.

Une adresse par dépôt

Ne pas réutiliser les adresses, pour préserver la confidentialité.

Le webhook fait foi

Le statut final vient du webhook ou d'un appel serveur, jamais du navigateur.

Dépôt public propre

Règle du hackathon : projet publié dans un dépôt GitHub public, README inclus.
